# AWSherlock v0.4.0

AWSherlock v0.4.0 expands the read-only scanner with opt-in Amazon Bedrock
configuration checks, positive workload-identity relationships, conservative
investigation Leads, a standalone investigation-oriented HTML report and bounded
service collection concurrency. It also publishes the deterministic regression
suite and runs it in Scanner CI without AWS credentials or live AWS calls.

## What's new

- 42 registered checks across 11 services, with the existing seven-service
  default scan unchanged.
- Snapshot schema v2 relationships and five conservative investigation Lead
  patterns.
- Investigation-oriented offline HTML that links Leads, findings, resources,
  relationships and coverage while keeping uncertainty visible.
- Opt-in `--max-workers` service-level concurrency within one live
  account/region scope. Account and region traversal remains sequential.
- A public deterministic test suite and multi-platform Scanner CI, including a
  configured standalone-browser report job.

## Amazon Bedrock security scanning

The new opt-in `bedrock` service adds two regional checks:

- `AWSH-BEDROCK-001` reports when a successfully validated Amazon Bedrock Agents
  Classic current DRAFT configuration has no associated Guardrail.
- `AWSH-BEDROCK-002` reports when the Bedrock Runtime model invocation logging
  facility has no active normalized destination/modality configuration.

The collector stores configuration categories rather than prompts, instructions,
model inputs/outputs, logging destination names or arbitrary AWS responses. The
logging check concerns the Bedrock Runtime facility and does not claim coverage
of every Bedrock inference endpoint.

## Relationships and AI workload identities

Schema-v2 snapshots can carry normalized positive `RUNS_AS` relationships for
Lambda functions, EC2 instances, Bedrock Agents and AgentCore runtime versions.
Bedrock execution-role evidence can merge with optional IAM identity-discovery
evidence into one logical edge with both provenance records. AgentCore identity
uses the inventory-reported runtime configuration version, so versions remain
distinct even when they belong to the same runtime.

No AgentCore security-check service was added. AgentCore runtime-version sources
can intentionally exist only as relationship references; no version-specific ARN
or resource is fabricated.

## Investigation Leads

Five deterministic patterns correlate exact findings and relationships into
reviewable investigation context. The AI workload pattern identifies a Bedrock
Agent or AgentCore runtime version that runs as the exact IAM role carrying an
existing broad-permission finding. Leads keep observed evidence, unknowns and
what is not proven separate. They do not claim effective access, exploitability,
compromise or a confirmed attack path.

## Investigation HTML reporting

Standalone HTML reports now present an overview followed by Leads,
relationships, collected resources, findings and coverage. Stable links connect
supporting evidence, including relationship-only AgentCore references. Coverage
gaps and `AccessDenied` remain visible, and a missing relationship is not treated
as proof that none exists. The report remains self-contained, escaped, offline
and free of external scripts, fonts, telemetry or API calls.

## Bounded parallel scanning

Live `scan` and `snapshot` commands accept `--max-workers N`. The default `1`
preserves serial behavior. Higher valid values bound concurrent registered
service collectors within one account/region scope; aggregation remains in
registry order and relationship projection/evaluation begins only after
collection is assembled. This is a task-concurrency bound, not an AWS API
requests-per-second rate limiter. SDK retries and service throttling still apply.

## Compatibility and limitations

- Snapshot schema remains v2; existing v1/v2 replay stays offline and no old
  snapshot is enriched while loading.
- Existing JSON, console and SARIF contracts remain unchanged.
- AWSherlock does not simulate effective IAM permissions or prove attack paths.
- The Agents Classic Guardrail check covers only the current DRAFT
  configuration, not published versions or deployed aliases.
- Bedrock Runtime invocation logging does not imply coverage of every Bedrock
  inference endpoint, and enabling logs requires appropriate data governance.
- AgentCore relationships cover the runtime version surfaced by normal inventory,
  not all historical or endpoint-pinned versions.
- Missing relationships and incomplete collection do not prove security.
- No action-group, Lambda action-target, workload-identity, network-reachability
  or automated-remediation graph was added.

## Install or upgrade

Install the stable release with:

```bash
pipx install awsherlock==0.4.0
```

Or in a virtual environment:

```bash
python -m pip install awsherlock==0.4.0
```

Upgrade an index installation with `pipx upgrade awsherlock` or
`python -m pip install --upgrade awsherlock`. The existing
`awsherlock --update` command intentionally installs GitHub `main`, which may be
newer than the latest stable PyPI release.

AWSherlock uses the standard AWS SDK credential chain and performs read-only AWS
API operations. No new scanner permissions are introduced by relationships,
Leads, HTML rendering, concurrency or the public test suite.
