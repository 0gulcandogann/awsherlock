# AWSherlock v0.5.0

AWSherlock v0.5.0 strengthens offline investigation without adding security
checks or changing the default live scan. It keeps 11 registered AWS services,
seven defaults, 42 checks, five conservative Investigation Lead rules and
snapshot schema v2.

## What's new

- Evidence-aware Lead Delta is available with `diff --include-leads`. The
  default snapshot-diff document remains version 1; the opt-in document is
  version 2 and keeps uncertain appearances or disappearances `UNKNOWN` when
  the available evidence cannot establish a transition.
- `awsherlock investigate` exports one minimized Investigation Evidence Pack in
  schema-v1 JSON or standalone HTML. It includes only the selected Lead's
  validated supporting findings, relationships, coverage and provenance.
- Opt-in `--identity-ai-production` observes AgentCore endpoint `liveVersion`
  and `targetVersion` routing and resolves each exact referenced immutable
  runtime version to its validated IAM execution role.
- `awsherlock coverage` derives deterministic schema-v1 Coverage Diagnostics
  from an existing snapshot and evaluation report without AWS access. It keeps
  recorded positive evidence, known limitations and unknown completeness
  separate.
- CLI discovery and Windows pipx self-update handling include the post-v0.4.0
  maintenance fixes while preserving the intentional GitHub `main` update
  channel.
- Package validation now rejects non-portable README image references so the
  AWSherlock logo can render from both GitHub and PyPI.

## AgentCore production context

Production routing discovery is explicitly opt-in and requires
`--identity-governance --identity-ai-services --identity-ai-production`.
It adds these read-only actions:

- `bedrock-agentcore:ListAgentRuntimeEndpoints`
- `bedrock-agentcore:GetAgentRuntimeEndpoint`

It reuses `bedrock-agentcore:GetAgentRuntime` for each exact live or target
version. A runtime endpoint positively `USES` its configured live and/or target
runtime version; that version `RUNS_AS` its own exact validated IAM role.
Different versions remain separate even when the runtime ARN is shared.

This is control-plane configuration evidence. It does not prove endpoint
reachability, successful deployment, invocation, traffic, effective IAM
permissions, exploitability or compromise. Published Bedrock alias/version
routing remains deferred; existing Bedrock DRAFT checks are unchanged.

## Coverage and investigation semantics

Coverage Diagnostics does not create a coverage score or overall PASS. A
recorded `COMPLETE` status concerns evaluation of supported checks over saved
facts, not exhaustive AWS inventory or account security. Missing findings and
relationships do not establish safety, absence, non-use or remediation.

Lead Delta, Evidence Packs and Coverage Diagnostics remain offline and make no
AWS calls. Evidence Packs use exact operation allowlists and omit raw SDK
responses, arbitrary issue messages, credentials, prompts and environment
values. Positive `RUNS_AS` and `USES` edges do not prove relationship-family
enumeration completeness.

## Compatibility

- Snapshot schema remains v2; historical v1 and v2 snapshots remain readable
  and are never enriched while loading.
- Default diff output remains version 1. Lead Delta is opt-in.
- Investigation Evidence Pack and Coverage Diagnostics each use schema version
  1.
- Existing console, JSON, SARIF and standalone HTML reporting contracts remain
  available.
- `--max-workers` remains opt-in, defaults to serial collection and bounds
  collector tasks rather than AWS API requests per second.
- No AgentCore check service, automatic remediation, effective-permission
  simulation, network analysis or confirmed attack-path claim was added.

## Install or upgrade

Install the stable package after publication:

```bash
pipx install awsherlock==0.5.0
```

Or in a virtual environment:

```bash
python -m pip install awsherlock==0.5.0
```

Upgrade an index installation with `pipx upgrade awsherlock` or
`python -m pip install --upgrade awsherlock`. The built-in
`awsherlock --update` intentionally installs GitHub `main`, which may be newer
than the latest stable PyPI release.

AWSherlock uses the standard AWS SDK credential chain and performs read-only AWS
API operations. The v0.5.0 regression suite is deterministic and credential-free;
the new AgentCore production-routing and Coverage Intelligence behavior was not
validated against a live AWS account for this release candidate.
