## Final architecture and implemented behavior

The existing collection → snapshot → Finding → Lead pipeline is retained.
A derived, reusable engine consumes one exact evaluation and correlation per
scope. Immutable investigation contracts reference the original Findings and
Relationships, retain all five patterns and preserve deterministic logical
identity. No duplicated Findings/Leads or snapshot schema changes are introduced.

Positive conditions are observed only after existing support/locator gates.
Review associations are inferred with explicit assumptions. Unassessed access,
reachability, criticality and the original not-proven conditions stay unknown.
Identity conflicts block scoring and move candidate observations to unknown.
Relevant coverage gaps and scope-wide failures remain visible, including when
there are no investigations. Existing Lead Delta resolution policy is unchanged.

Priority uses five independently capped configuration categories, bounded 0–7,
with evidence references and individual explanations. HIGH >=5, MEDIUM >=2,
otherwise LOW; assessed results remain PROVISIONAL. Identity inconsistency yields
UNASSESSED/BLOCKED and null score. Finding severity and original Lead priorities
are untouched. This does not quantify effective access, impact or confidence.

Standalone HTML adds accessible investigation records and an offline SVG graph.
Selection, label highlighting, association filtering, keyboard node inspection,
text evidence links, legend and bounded rendering are implemented. At most 100
graphs are embedded, with 80 nodes/160 edges per selected view; omitted counts
are displayed, dangling rendered edges are removed and text remains available.
Observed configuration/support edges differ from inferred associations; blocked
candidate relationships are dashed. HTML/script/DOM escaping is tested.

## Public CLI, schema and compatibility

```bash
awsherlock investigate facts.json --contextual --output json
awsherlock investigate facts.json --contextual --output html --report-file investigations.html
awsherlock investigate facts.json --contextual --lead-id PATTERN:FULL_SHA256
```

The first mode exports `kind: contextual-investigations`, integer schema version
1 and priority policy version 1. It contains conditions, supporting references,
coverage gaps, priority factors/explanation and manual actions. JSON defaults
to stdout. HTML requires a fresh destination. Incomplete artifacts exit 1;
provisional priority alone does not. Selection/output errors exit 1; usage
errors exit 2. Without `--contextual`, the existing exact-one-Lead Evidence Pack
contract remains unchanged and still requires `--lead-id`.

Snapshot v1/v2, default scan JSON, Evidence Pack v1, Coverage Diagnostics v1,
Lead v2, diff/Lead Delta, suppression behavior, Finding severity and automation
thresholds remain compatible. The graph is automatic in scoped scan HTML;
report-only HTML callers retain the explicit context-unavailable state.
No runtime dependencies or supported Python floor changes were introduced.

## Unexecuted validation and security limits

The six browser tests require rerunning in a permitted local environment or
the dedicated Chrome CI job: Evidence Pack opening; graph selection/filtering;
standalone contextual print/XSS; report opening; finding filters/sorting/empty
states; mobile report layout. The host has `Seccomp: 2` and `NoNewPrivs: 1`;
Unix socket pairs were allowed, but their `SO_PASSCRED` option and AF_INET socket
creation returned EPERM. Chromium's version
command works, but headless startup fails configuring crashpad sockets. Required
execution permissions are unavailable; no host security policy bypass was tried.
Browser launch diagnostics now include bounded stderr and exit codes; CI fails
if its required browser is absent instead of silently skipping the suite.
JavaScript parsing and static XSS tests do not replace browser interaction tests.

**Live AWS validation: NOT EXECUTED.** No AWS account was accessed, no credentials
were inspected and no resources were provisioned. EC2/Lambda/IAM, Bedrock/AgentCore,
denial, cross-account, partial API and throttling scenarios have a documented
authorized live procedure and an explicit NOT EXECUTED ledger. Synthetic SDK
retry behavior does not prove service-side throttling behavior in a real account.

All integration tests executed here are synthetic/offline, including the
collector smoke, CLI round trips, same-capture replay and actual SDK retry-loop
test with synthetic HTTP. No external account or remote CI run is implied.

No exploitability, effective-IAM, routing/NACL, attacker credential access,
production traffic or remediation conclusion is supported. Identifiers/ARNs
remain sensitive. Historical snapshots lack authoritative asset criticality,
relationship-family completion and IAM incarnation continuity. A future support
module extraction could reduce private-helper coupling to existing Lead Delta;
this release deliberately avoids changing its established policy.

An independent read-only code review found no Critical/Important issues. Its two
minor observations were addressed: strict reference digest validation and a
multi-scope incomplete-coverage merge regression. Final release validation is
limited by the unexecuted browser and live-AWS checks above; publication remains
under owner control.
