## Successful: Ruff and Black cleanup

System-installed **Ruff 0.17.1** and **Black 26.10.1** were used; the existing
`pyproject.toml` dev extra pins these exact versions. Runtime dependencies and
package version 0.5.1 are unchanged. Both tools target Python 3.11 with a
100-column preference. Ruff's existing `E4`, `E7`, `E9`, `F` rules are unchanged;
no blanket suppressions or source exclusions were added.

The initial 314 Ruff errors included 233 F811 errors from imported fixture names
shadowed by pytest parameters. Shared fixtures now register explicitly through
`tests/conftest.py`, using distinct service context names and deliberate
`__all__` exports. Original fixture functions, scopes and owning module state
remain intact. A collection audit compared all **1773 test nodes** before and
after migration: every node retained exactly the same fixture provider functions
and scopes. Direct fixture-factory use remains intact. Remaining edits remove
unused imports/bindings, replace three assigned lambdas with equivalent named
functions, rename ambiguous test variables and remove unnecessary f-prefixes.

Black formatting was verified across **162 Python files**. AST comparison
immediately before and after formatting found **zero syntax-tree changes**.
The distinct lint/fixture edits were reviewed separately; 79 test modules were
also AST-compared after accounting for the reviewed imports, fixture names and
style transformations. Isolated S3, IAM and
CLI module runs passed 18, 15 and 85 tests respectively. `ruff check .` passes
with zero errors; `black --check .` and `git diff --check` pass.

Black's default process pool cannot bind its forkserver Unix socket (EPERM).
`BLACK_NUM_WORKERS=1` avoids that operation, but cross-thread event-loop wakeups
also hit EPERM when sending on a Unix socket pair. Formatting and independent
`black --check --no-cache FILE` verification therefore ran sequentially, one
file per Black invocation, before the repository-wide cached verification:

```bash
ruff check .
BLACK_NUM_WORKERS=1 XDG_CACHE_HOME=/tmp/awsherlock-quality-cache black --check .
.venv/bin/python -m pytest -q
git diff --check
```

No formatter internals or host security settings were changed. The single-file
verification bypasses no formatting checks. Normal local terminals can use
`black .` and `black --check .` directly. No typing checker is configured.

A minimal native Chrome `about:blank` launch with its sandbox enabled also exited
-5 at the same Crashpad operation. An independent Python socket probe denied
`SO_PASSCRED` with EPERM on both Unix stream and sequence-packet socket pairs.
The process's PID 1 executable is `codex-linux-sandbox`; the process runs as UID
1000 with the seccomp state below. This is an enclosing execution-environment
restriction, reproducible without Chrome, rather than evidence of an AWSherlock
report bug. The host policy source is unavailable, so its exact rule remains
unidentified. The subsequent user-reported validation outside this environment
passed all six browser tests, as recorded above.

Normal test runs now keep Chrome's sandbox enabled. The explicit test-only
`AWSHERLOCK_TEST_BROWSER_NO_SANDBOX=1` opt-out preserves the previous isolated
GitHub runner launch mode, where it is configured explicitly in Scanner CI.
It is unnecessary for the normal-terminal commands below and does not solve
host EPERM restrictions. No new dependency or product behavior change was made.

Direct local probes separated the exact operations:

| Operation / state | Observed result |
| --- | --- |
| `socket(AF_UNIX, SOCK_STREAM)` | Allowed. |
| `socketpair(AF_UNIX, SOCK_STREAM)` | Allowed. |
| `socketpair(AF_UNIX, SOCK_SEQPACKET)` | Allowed; matches Crashpad's socket-pair type. |
| `setsockopt(SOL_SOCKET, SO_PASSCRED, 1)` on the Unix sockets | **EPERM (errno 1)**. This is the confirmed first browser IPC blocker. |
| `socket(AF_INET, SOCK_STREAM)` | **EPERM (errno 1)**; Internet socket creation is separately restricted. |

The process reports `Seccomp: 2`, one seccomp filter and `NoNewPrivs: 1`.
The host filter definition/audit log is not exposed, so an exact host policy rule
or configuration-file line cannot be identified. These are syscall-level
observations, not a claim that all later browser requirements are known.
`NoNewPrivs` alone does not establish the cause of a socket-option denial.

Crashpad's [primary source](https://chromium.googlesource.com/crashpad/crashpad/%2B/a11243e8f12a2d9a8c5c3b4b68c7f2b9cc6baa42/util/linux/socket.cc)
creates a Unix sequence-packet pair and enables `SO_PASSCRED` to receive process
credentials. The observed option denial matches this startup failure. The
original harness passed `--no-sandbox`; that did not relax the parent
process's host restrictions. The updated harness retains the browser sandbox
by default. No host policy bypass, sudo or permission change was attempted.

No page opens inside Codex, so browser interactions cannot be verified here.
The normal-terminal automated pass above covers the implemented DOM assertions;
manual visual inspection remains unreported. Static escaping/syntax tests alone
do not substitute for browser checks. Earlier
