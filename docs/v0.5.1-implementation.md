## Design and compatibility decisions

The supplied release specification authorizes sequential implementation directly
in this repository, with no commit/tag/publish. Work stays on the existing
the existing development branch. No additional design approval is needed.

Add a derived engine rather than rewriting Lead correlation or embedding data
in snapshots. Reuse the Evidence Pack's exact support/locator and export gates
through a small internal adapter; do not reevaluate once per Lead. Keep old
Evidence Packs and CLI invocations unchanged. `investigate --contextual` exports
all contextual investigations; optional `--lead-id` selects one. Standalone
scan HTML automatically includes contextual investigations when scopes exist.

Priority is a bounded indicator score, independent of severity/confidence:
exposure 2, broad permission 2, metadata weakness 1, governance/usage 1,
observed workload binding 1 (each category at most once). HIGH >=5,
MEDIUM >=2, LOW otherwise. Every factor cites evidence. Missing evidence never
subtracts points or proves safety; identity conflicts block scoring and move
claims into unknown. All supported patterns retain unassessed effective-access
or impact conditions, so priority is PROVISIONAL with explicit reasons.
No asset criticality is inferred: the snapshot has no authoritative criticality
contract. Graph associations are dashed; observed relationships are solid.

## Sequential implementation plan

1. [x] Evidence foundation: frozen typed contracts in `investigation_models.py`,
   stable reference IDs and detached canonical serialization; extract reusable
   support adapter without changing Evidence Pack v1. Test all reference kinds,
   invalid inputs, deterministic output and existing pack regression.
2. [x] Engine: `investigation_engine.py` adapts all five patterns using one exact
   evaluation and correlation; support gaps, scoped coverage, explicit unknowns,
   factor-based priority and manual actions. Test permutations, v1/v2, denials,
   conflicts, unknown reachability, provenance minimization and Lead Delta.
3. [x] Reporting: optional contextual mode on `investigate`; existing scan HTML
   gets an accessible evidence list and offline SVG via a bounded graph builder.
   Test selection, CLI exits/exclusive writes, XSS, node/edge integrity, limits,
   filters, empty data and browser interactions when execution is available.
4. [x] Hardening/validation: synthetic end-to-end fixtures, repeatable offline
   consistency checker and read-only live validation procedure; retain bounded
   SDK retries and identity isolation. No live AWS without explicit permission.
5. [x] Release: architecture/schema/priority/graph docs, README and contributor
   corrections, v0.5.1 release notes and metadata; full regression, compile,
   diff checks, wheel/sdist validation, isolated installed-wheel smoke.

Review focus: ambiguous ARNs; relationship-only AgentCore versions; selected
reports and suppressions; hostile strings in JSON/script/SVG; large connected
investigations without dangling rendered edges. Test each at its owning phase.
